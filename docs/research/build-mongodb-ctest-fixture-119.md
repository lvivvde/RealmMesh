## 范围与约定

用户确认一次完整 CTest 可以共享一个真实单成员 `rs0`，每个 GTest 用例及
DevServices 用例使用独立数据库。全部旧断言、真实 mongosh 回读、majority 与事务、
原初始化截止时间及串行完整测试保持。独立运行仍自启实例，公开默认构造保持独立所有权。
该决定明确修订 ADR-0011 原先每例自启的测试生命周期句子，见该 ADR 的日期修订。

准备、清理、契约三项新增 CTest 都计入完整入口。守护进程绑定 CTest PID 与出生时间，
在正常清理或所有者异常消失时回收真实后端与数据；借用前检查所有者祖先关系。
每条 DevServices 的重启/恢复仍使用该条用例的数据库，不共享玩家数据。

## 真实失败反馈与审查修复

原型的准备/Primary、跨进程数据库隔离、错误副本集准备失败与 SIGKILL CTest
回收通过真实 CTest、mongod、原生初始化器及 mongosh 验证。
Standards 审查发现父进程只等待守护进程 2 秒，而守护进程需依次回收两个叶子进程；
Spec 审查发现 shell 的借用未验证祖先，可能借用无关 CTest 的后端。

新增真实准备中断守卫让原生初始化器等待不可达的本地端口，并忽略 TERM 以实际触发
KILL 预算；后端仍是真实 mongod，不用替身。修复前可复现遗留数据目录；增加
守护进程独立 5 秒收尾预算后通过，两个叶子进程仍各为 2 秒。
无关所有者借用在修复前返回成功，增加 CLI 祖先校验后明确拒绝。
五项真实契约完整通过（8.943 秒）。一次相对源码路径误用导致的嵌套启动失败单独保留，
随后按 CMake 的绝对路径重跑，不把该失败当作正确回归反馈。
固定代码版本 `6ebce52271119528ec27e0ad1ca11097ccb8c901` 的两轴只读复核均为 0 项剩余发现。
