## 范围与实现

独立 `realmmesh_mongodb_fixture` 使用现有固定版本 MongoDB C 驱动初始化真实单成员
`rs0`，并等待 `hello` 同时确认副本集名称及可写 Primary。六个 GTest 集成目标显式
依赖辅助程序，DevServices 的 CTest 环境传入同一路径。初始化器在自己的进程中
管理 C 驱动生命周期，被测进程仍拥有唯一 C++ 驱动实例。

所有业务断言及 mongosh 数据回读保留；GTest 进程内可共享 mongod，但每例数据库
独立，DevServices 每条用例仍启动自己的实例。原 30 秒初始化截止时间由剩余预算
传给辅助程序，覆盖端口等待、驱动调用与 Primary 就绪；显式路径缺失或失败不能
回退成成功。回收先恢复暂停的服务，TERM 最多等待 2 秒，再 KILL 并回收，随后
清理本例数据目录。产品、手动开发和共享 MongoDB 的路径未改。

真实后端契约通过公共 CLI 与 MongodProcess 构造边界验证初始化、幂等重入、Primary、
初始化失败、截止时间及失败回收。构造失败守卫同时覆盖缺失初始化器和真实 mongod
暂停后原生初始化器超时。先复现失败，再实现修复；全部日志保留。

## 筛查与失败证据

正式实现前，对相同冻结源码的完整 667 项做单次只读 shell 诊断：Mac 59 次初始化
共 32.214 秒、48 次 Primary 检查共 14.825 秒、11 次 ping 共 3.698 秒，12 次数据
回读共 4.079 秒；Lima 分别为 12.326、8.055、2.048（12 次，含一次正常失败重试）
和 2.190 秒。调用墙钟和仅用于归因，不能代替完整入口。

Mac 原生转发探针完整 667/667 通过，CTest 实际墙钟 358.802 秒；旧 shell 诊断为
398.431 秒。这是实施可行性筛查，缺少配对和新增守卫，不进入正式门槛统计。
首次受限沙箱运行无法探测端口/进程，失败并跳过；首次转发探针误判参数位置，
中断自己的 CTest 后修复，完整重跑通过。无效结果、退出码和原始日志均保留。

Lima 首轮正式系列在第三组后侧出现两项失败；全程监测捕获 17 次墙钟与单调时间
大幅不一致，首次墙钟跳变约 590 秒，与宿主 2026-10-09 00:57 合盖休眠及后续
Maintenance Sleep 对齐。频率/tick 仍为 0/10000，不是此前 P6 的频率漂移复发。
原系列全部保留并整体排除，未挑选其中通过或较快的样本拼接。新的稳定时钟系列
沿用完全相同来源、工具、资源与顺序，先重放失败用例（2/2 通过，104.90 秒），
再做完整三组替代采样。采样期间使用本轮拥有的防睡眠断言；验证结束只释放该进程。

正式准备时 R0 首次重新配置后发生额外编译/链接，记录为准备过渡，不计为热入口。
