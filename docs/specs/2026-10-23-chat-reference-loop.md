## 范围

客户端复用已认证的 Realm Session；Realm 按当前选角与 Scene Binding 派生聊天身份、频道和权限，
通过独立服务链路调用 Chat。Chat 是独立 `chat` 服务身份；Gateway 不接收或转发聊天业务。
提供 Scene 内频道，以及同一逻辑 Realm 内跨 Scene 的频道。首版采用一个 Realm 进程、两个
逻辑 Scene Shard、至多两个 Chat 实例；不同逻辑 Realm、多个 Realm 进程的全局账号顶替不在本阶段。

不包含消息历史、离线补投、私聊、好友、邮件、公会、审核后台、外部消息代理、动态频道迁移、
跨机器业务验收及 M5。发送成功不升级为玩家数据持久提交，也不引入 Redis 或 MongoDB 聊天集合。
规格提案PR #181只修改文档和任务。C1按需增加实际proto/编解码，仍不预建服务目录、配置或注册（ADR-0003）。

## 频道与权威

| 对象 | 权威与边界 |
|---|---|
| 账号、当前角色、Realm Session | Realm；客户端提供的账号、角色、Realm/Chat 实例身份均不可信 |
| Scene Channel | `(realm_id, scene, shard_id)`；同一逻辑分片共享频道，Scene 承载变化不改变频道 |
| Realm Channel | `(realm_id, realm, 0)`；该逻辑 Realm 内已选角的在线角色共享，允许跨 Scene |
| Chat Membership | 单角色、单频道的在线资格；由 Realm 派生并通过已认证链路安装到 Chat |
| 频道受理与顺序 | 配置指定的唯一 Chat 实例；该频道所有发送由同一个串行状态机裁决 |
| 发现 | etcd 只发现指定实例端点，不授予成员资格，不让两个实例同时受理一个频道 |
| Scene Binding、Confirmed Location、训练 | 保持既有持久边界，Chat 不能写入或重新解释 |

未选角不能收发。已选角可加入 Realm Channel；Scene Channel 另要求当前 Scene Binding 已确认且
Scene 可用。Scene 故障时暂停该 Scene Channel；Realm Channel 不因 Scene 故障自动退出。
首版仅有分片 1/2 和一个 Realm Channel，共三个配置频道；拒绝客户端任意创建频道、跨 Realm 或
伪造 shard_id。角色名字不充当发送者身份，通知使用 Realm 派生的 character_id。

每个频道通过服务端允许列表静态映射到精确的 Chat instance_id。C2–C3 可由一个 Chat 承载三频道；
C4 用两个 Chat 验证分开承载，Realm Channel 仍只有一个排序者。不自动把失败频道路由到另一个
候选，不做双写或广播竞速。运行中迁移频道不在本阶段；配置变更需停用旧承载并重新建立频道轮次，
不能仅因发现列表变化就宣称换主或保持连续。多实例不等于同频道多主。

## 成员资格与转场

每条成员资格携带 Realm incarnation、Realm Session binding、membership_generation，
以及 Scene Channel 所对应的 Scene Binding 版本。Realm 只允许当前会话引用自己的资格；
客户端回传的标识只用于选择已知资格，不授予权限。Realm Channel 的资格不随 Scene 转场更换。

Chat 为每个已认证 Realm 实例维护唯一活动链路代次；新链路受理时先使旧链路失效。
资格只能在所属链路、当前会话和该频道代次上使用。旧连接请求、迟到响应、旧连接清理不得影响
新资格；链路关闭时回收它的资格和回执。这里不解决两个同时运行且配置冲突的 Realm 主进程。

membership_generation由同一条已认证Realm–Chat活动链路统一严格递增分配，跨该链路的角色/
频道不复用；资格本身仍是单角色、单频道，转场不改变已有Realm Channel资格。Chat只保留
活动资格和每条链路一个highest_seen_generation，不按离线会话累计无界墓碑。

- 同代次且完整参数相同的活动JOIN，幂等返回第一次安装时的原Epoch/W，不重取W、清除
  发送回执或重置client_send_seq；同代次不同参数拒绝。丢JOIN响应期间已受理的W+1不能被重试跳过。
- 新JOIN只有generation大于highest_seen才可安装并推进该水位；低代次且已无活动记录的JOIN
  拒绝为失效。别的更高代次加入不使仍活动的低代次资格失效。新JOIN在链路上按分配顺序发出；
  若乱序的未安装JOIN被明确拒绝，后续须用新代次显式重新加入，不能伪装成原水位连续。
- LEAVE按完整旧资格条件删除，并推进highest_seen到至少该generation；即使JOIN尚未到达也
  标明该代次失效。迟到JOIN不能复活它，旧LEAVE不能移除已安装的新资格，重复LEAVE幂等。
- 计数耗尽拒绝继续使用，不回绕；重新认证取得新链路代次后再分配。旧链路任何请求或完成
  都不能推进新链路水位。链路关闭统一释放该链路状态。

Scene 转场开始时，Realm 立即暂停源 Scene Channel 的新发送和客户端推送，异步撤销源资格；
移动/转场持久流程不等待 Chat。目标 Scene 完成既有激活后，异步加入目标 Scene Channel，
取得新资格；失败只使该频道暂不可用。提交前转场失败则重新加入已确认源频道；提交后目标激活
未恢复前不伪装为可用。Scene 同分片重建也按当前有效 Scene Binding 重新加入；逻辑频道不变。

旧资格的 SEND 与撤销在 Chat 串行裁决：撤销前已经受理的消息不回滚；在途发送按 Chat 的实际
受理顺序判定，不能承诺转场与聊天跨服务原子生效。撤销生效后的旧 SEND 必须拒绝。
即使撤销响应丢失，Realm 在本地暂停后也不再向该客户端交付源频道消息；旧清理不能撤销新资格。
Realm Session 关闭、同账号顶替或重启立即失效本地所有资格，重登后重新加入，不能复用旧回执。

## 排序、加入水位与可见性

Chat 每次启动使用新 incarnation；频道身份和该 incarnation 一起形成 Chat Channel Epoch。
每个频道在一个 Epoch 内从 1 分配连续 channel_seq，仅受理新消息时递增，拒绝和重复重试不占号。
空频道仍保留该进程内最后水位；不能删除后在同 Epoch 中从 1 复用。计数耗尽停止受理，禁止回绕。
不比较不同频道或不同 Epoch 的 seq；Chat 重启后允许新 Epoch 从 1 开始。

加入确认返回当前 Epoch 与已受理水位 W。加入者只接收 seq > W 的在线消息，不能把入场前消息
伪装成历史补投。资格安装、取 W 与后续推送衔接由频道同一状态机完成；Realm 在交付加入确认前
有界缓存后续事件，不能在快照/订阅交接处漏消息。每个有效成员都接收消息推送，包括发送者；
发送回执不代替推送，也不推进客户端的通知水位。

同一资格下客户端只按递增水位交付，重复通知去重。若检测 seq 缺口、Epoch 改变、链路失效或
缓存满，发出明确的 ChatUnavailable/缺口状态并暂停连续交付；不得静默丢弃后继续声称连续。
重新加入从新 W 观察后续消息，不回放缺口内容。资格更换后的迟到事件按会话、频道、代次、
Epoch 和加入水位过滤，不能泄漏给转场后的角色或新 Realm Session。

## 受理、回执与不确定结果

每条 Chat Membership 独立使用 client_send_seq，新资格从 1 开始；它与 scene_seq、训练序号以及
其他频道的发送序号无关。同一资格只允许一个发送在途，新的有效发送必须为 last + 1。
SEND 绑定当前资格、预期 Epoch、序号及原始 UTF-8 文本；Chat Receipt 返回消息的频道/Epoch/seq。

- Accepted：唯一排序者已在内存中登记本次消息与去重结果，并受理在线分发；不是 MongoDB
  持久确认，不表示每个接收者已收到、阅读或能够离线恢复。
- Rejected：确定未受理，例如资格无效、文本错误、限流或受理队列满；不推进发送或频道序号。
- Unknown：派发后超时、回执丢失且未核实、或排序状态丢失；不能作为“未发送”或自动重发许可。

同一有效资格和 Epoch 内保留最后已受理序号、原始参数及回执。完全相同的最后一次发送
返回原回执，不重复分发；同号不同参数拒绝冲突，过旧或跳号拒绝。GetChatState 可返回该资格
最后回执；查询暂时没有记录不证明迟到请求不会受理，应保持 Unknown 或用原号/原参数重试。
资格结束或 Chat 重启后不承诺找回旧回执；旧 Epoch/旧资格不能在新轮次自动重放。
新资格下的发送是应用显式发起的新消息，不能把旧 Unknown 偷换为确定失败。

接受边界必须为一个原子状态迁移：先预留有界受理资源，再同时登记回执、推进水位并安排分发。
资源不足在该边界前拒绝；边界后的接收者交付失败不能撤销已受理回执、复用频道序号或重复广播。
进程在受理后崩溃可能丢失内存状态和部分尚未交付消息，恢复必须暴露新 Epoch，不承诺持久或
端到端 exactly-once。仍在线且未失效、未报缺口的成员，在同 Epoch 观察到相同频道顺序。

## 线协议与内部认证计划

C1已在`chat/v1/chat.proto`定义以下契约，客户端1701–1706、内部1801–1803；字段、有限原因、
错误码3201/3202、计数和字节上限以[protocol.md](../protocol.md)及proto为准。C2已实现内部服务监听和排序，C3已实现Realm/客户端接线。

| 客户端概念消息 | 必需内容 |
|---|---|
| GetChatState / ChatState | 单频道资格状态、Epoch、加入水位、最后发送序号/回执；不返回聊天历史 |
| SendChat / ChatSendResult | 频道选择、当前资格代次、预期 Epoch、client_send_seq、文本；Accepted/Rejected/Unknown、有限原因及回执 |
| ChatMessage | 频道/Epoch/channel_seq、发送角色、文本；资格上下文用于 Realm 过滤，不能由客户端指定发送者 |
| ChatUnavailable | 频道、有限原因、是否需要重新加入；不能表示 Scene 落点或训练丢失 |

参考客户端复用 `realmmesh-edge/1`、Envelope v1 与现有 Realm 连接，提供窄 Chat 接口；等待
聊天、Scene、心跳和训练响应时分类保留其他推送，各缓存有界；不能靠只读取当前请求消息吞掉通知。

Realm–Chat 规划使用独立 TLS/TCP、专用 ALPN `realmmesh-chat/1`、服务 CA、双向证书和精确
DNS SAN 允许列表，且校验 realm_id、配置承载与链路代次。etcd 发现或客户端 EnterRealm 票据
均不能代替服务认证。内部操作至少包含链路握手、JOIN、LEAVE、SEND、STATE 与消息推送；
每次请求核对资格所属链路，迟到 LEAVE 条件匹配旧资格。未知服务身份、错误 ALPN、证书/
Realm 不匹配和越权频道均拒绝；密钥、凭据、原始聊天文本不写日志或指标标签。

Chat 在 C2 真正实现时才注册到 apps/mesh_host；game/realm 与 game/chat 只依赖 game/common、
proto 及 framework，不相互 include/链接，也不依赖 game/client（ADR-0014）。Chat 自己解析配置、
持有频道状态；不让 framework 知道聊天协议或服务身份。不新增 Chat 的 AccountStore 或通用存储服务。

## 有界资源与故障隔离

首版上限已由C1在`chat_limits.hpp`固化，C2已实现服务端配置和记账，C3实现Realm侧接线与记账；这些是资源限制，不是容量测量：

| 资源 | 上限与处理 |
|---|---|
| 频道/承载 | 一个逻辑 Realm、三个配置频道、至多两个 Chat；每频道一个配置承载 |
| 在线角色/成员 | 至多64个角色、每角色至多2个资格；Scene Channel至多16人，Realm Channel至多64人 |
| 文本 | 1..512 UTF-8字节；拒绝非法编码、NUL、ASCII控制字符（含CR/LF及DEL），不隐式改写正文 |
| 发送 | 每资格1个在途；Realm按角色跨频道/承载共享5条/秒、突发10条；Chat每资格另做同上限校验，拒绝带有界重试建议 |
| 内部请求 | 每Chat实例至多64个（含运行、排队和未收结果），每Realm链路至多8个排队 |
| 时间 | Realm–Chat单次操作及排队总截止1秒；有限重试不延长本次截止 |
| 推送 | 每实例至多1024个待分发事件且总载荷至多4MiB；Realm每客户端/参考客户端各至多256个通知且总载荷至多256KiB，先到任一上限即满 |
| 链路/公平性 | Chat至多16条传输连接（含握手），每活动Realm实例一个有效链路；每处理轮次至多64个请求/64个推送，每资格每轮至多受理一个新SEND |
| 出站 | Chat每Realm链路至多1MiB待发送；单消息接收者至多64个，单个Envelope仍不超过64KiB |

计数与字节预算同时生效，包含排队、执行和未收结果的真实占用，C1/C2固化并覆盖边界值。
角色合计名额及发送速率由唯一Realm入口计数，待撤销/未收结果也计入占用；每Chat实例再以
同一上限做本地防御，不能把两个实例各自限额误称为跨实例总限额。
单角色不能独占实例；限流/队列拒绝可见。
慢客户端导致服务端出站满额则关闭该 Realm Session，其他成员和 Scene 分片继续服务；Chat 的
Realm 链路出站满额则终止该链路的资格并明确恢复边界，不能静默丢弃消息。

Chat 使用与 Scene/训练分别计数的队列、IO执行和完成通道；帧线程不执行同步连接、网络等待或
聊天历史访问。Chat 未配置、发现缺失或鉴权失败时 Realm 仍能启动，移动、转场、心跳和训练
保持原有截止及结果；失败只影响聊天。恢复后重新认证、安装资格并读取新 Epoch/W，禁止无限
后台重试或无限停机清理；失败和强制停止都回收服务、etcd及测试MongoDB并核对监听端口。

## 可观测与验收

至少覆盖发送 Accepted/Rejected/Unknown 数与延迟、有效成员数、待交付数、队列/限流拒绝、
旧资格拒绝、回执重放、通知缺口和链路恢复。零值拒绝计数显式发布；进入、发送、恢复的实际
HTTP指标样本随验收保留。标签仅用操作、频道种类与有限结果/原因，不能用角色、频道具体ID、
消息序号、Epoch或正文作为标签。稀疏结构化日志只保留排障必需的上下文，不写聊天正文。

| 必须覆盖的边界 | 通过证据 |
|---|---|
| 同Scene与跨Scene频道 | 两个真实账号选角，消息含发送者；双方同频道水位连续且顺序相同 |
| 加入与重复重试 | JOIN响应丢失夹入W+1，同代次重试返回原W且不清发送回执；LEAVE先到、旧JOIN/LEAVE与新代次竞争不复活旧资格；SEND回执丢失同号重试只分发一次，冲突拒绝 |
| 转场与Scene重建 | 旧Scene资格不再交付；新资格可收发，Realm Channel保持；数据库落点/场景序号正确 |
| Chat隔离 | 停掉承载A后其频道失败可见；另一Chat承载频道、Scene移动/转场/训练/心跳继续 |
| 重启与不确定 | Chat/Realm SIGKILL、同名重启、旧链路迟到回包；旧Epoch拒绝，新W可继续，Unknown不伪装失败 |
| 背压/饱和 | 真正服务端TLS出站满额、客户端缓存溢出、内部队列满、截止；不以另一种队列替代证明 |
| 身份与权限 | 伪造发送者/频道、未选角、错误服务证书/ALPN/Realm、旧资格和旧清理被拒绝 |
| 回收与报告 | 正常/异常停止无夹具子进程或监听遗留，缺组/缺HTTP指标/跳过/失败均使报告非零 |

外部系统事实使用隔离真实 etcd、MongoDB 和生产服务；不涉及外部系统事实的频道状态机测试
可用内存数据。故意丢弃内部响应可以使用真实mTLS边界替身，但不能据此宣称真实进程故障或
真实服务端背压已通过。测试永远不连接共享开发 MongoDB。

C5以所选preset的实际binaryDir生成冻结报告，记录源码/工作树差异、配置SHA256、环境/传输、
发现清单、逐例结果、数据库/回收属性、HTTP样本、原始日志和排除项。完成条件为macOS/Linux
当前源码全量、两平台各三次完整Chat多进程验收、既有Scene回归及Linux QUIC/M1–M4门禁全部通过；
双轴审查与文档状态同步，保留失败证据和可校验持久归档。此时才能关闭阶段5父任务。
