# 构建性能约束与检查清单

新增或修改 C++ 代码、构建流程、生成文件或测试夹具时使用本页。目标是减少不必要的编译和反馈等待，同时保持业务行为与完整验证。规则来自已实施的 P1–P6；设计取舍见[接口边界决策](../research/interface-boundaries-proposal.md)和[构建工具与缓存决策](../research/build-tool-cache-decisions.md)的实施记录。

## C++ 与依赖边界

- 公共头只暴露消费者需要的类型与契约。普通配置值和事件消费者使用轻量头；Lua 解析、绑定和完整 runtime 头由真正需要它们的实现或消费者显式包含。
- 指针、引用及允许不完整类型的声明优先前置声明；按值成员、模板和内联实现需要完整定义时保留必要 include。实现专用依赖放在 `.cpp` 或私有头，头文件独立包含应可编译。
- CMake 使用需求与公开契约一致：实现依赖用 `PRIVATE`，公共头真实需要的依赖才传播。静态库的 `PRIVATE` 依赖仍可能参与最终链接，拆头的收益用实际编译名单核验。
- 新拆分应切断真实依赖传播，保留现有普通配置/Gateway 头的编译守卫。Lua 通用绑定能力、线程归属、热更失败行为及对象生命周期按接口决策保留；新增 PIMPL、虚接口或更深拆分先提供热点证据与具体范围。

## 构建与生成文件

- 构建、测试、启动和验收共享所选 preset 的实际 binaryDir；沿用公共目录查询与资源预算入口。编译 jobs 与测试 jobs 分开，预算按运行环境的 CPU/有效内存确定，显式覆盖仍需检查内存压力。
- 配置及生成头在相同输入下保持内容和 mtime 稳定；恢复已经相同的源码字节时保留 mtime。新增生成规则登记真实输入、工具、产物与消费者顺序，验证删除单个产物能恢复，随后无操作构建稳定。
- 沿用严格 ccache 校验和兼容桶。源码、头、宏、flags、编译器及生成输入变化应正确失效；缓存未命中走正常编译，编译错误按原错误返回。Ninja、Make 与缓存开关的用法以 [README 构建说明](../../README.md#构建)为准。

## 验证与性能结论

- 测试归类、快速入口与完整运行条件以 [tests/README.md](../../tests/README.md)为准。夹具调整保留每个断言、真实后端和隔离要求；固定等待如需替换，先证明新的就绪/稳定条件仍能捕获原失败边界。
- 公共头、跨模块、生成依赖或构建流程变化，完成受影响检查与完整回归。涉及生成器或缓存时验证对应回退；涉及 QUIC 时按 `AGENTS.md` 的平台能力与 Linux CI 门槛验证。
- 声称提速前按[实施与验收约定](../research/build-implementation-acceptance.md)冻结版本、工具、环境、缓存状态和测试范围，取完整连续计时与配对样本，同时记录实际编译/链接工作量。编译、链接和测试等待分别归因；合集变化单列，失败与排除原因保持可见。
- P6 的首批性能验收未通过，当前结论及有界后续以[阶段报告](../research/build-optimization-results.md#p6双平台最终复测与有界后续决策129)和 [#119](https://github.com/lvivvde/RealmMesh/issues/119)为准。既有百分比是冻结条件下的结果，不能作为新代码或新机器的性能保证。
- 报告保留精简逐次结果、冻结信息和复现入口；大型原始日志与时间线放入持久归档，仓库记录链接和归档 SHA256。失败证据同样保留，临时目录不能作为唯一交付位置。

## 提交前检查

- [ ] 每个新增公共 include 和传播依赖都对应真实消费者；相关头独立编译及现有守卫通过。
- [ ] 涉及配置/生成规则时，相同输入稳定，单个产物删除恢复及后续无操作检查通过。
- [ ] 已完成与改动范围匹配的验证，注明平台能力、失败或未验证项；性能声明附真实配对证据。
- [ ] 文档同步到实际行为；结构、协议或领域词变化按 `AGENTS.md` 更新对应权威文档。
- [ ] 新增证据可持久访问与校验，仓库摘要能直接定位结论及复现方法。
