# Chat 首版提供在线受理与单频道排序，回执不承诺持久送达

---
status: accepted
---

阶段5承诺在线频道、消息顺序与故障反馈，历史和离线补投不在范围。Scene 已确认落点必须持久
（ADR-0015），但沿用它的每动作MongoDB提交会给Chat引入消息存储和恢复交付承诺。本提案选择：
每频道一个配置指定的Chat排序者，在一个Chat Channel Epoch内串行分配水位，以有界内存保留
当前资格的最后回执；Accepted只表示在线受理，不表示全员送达、阅读或崩溃后可恢复。

真实备选是持久消息日志配合投递确认，或由多个Realm并行转发。前者需要额外定义历史保留、
消费游标与重启补投，超出本阶段；后者没有同频道唯一顺序及统一的幂等边界。首版使用固定
频道承载映射，Chat故障不自动在另一实例复用序号；重启创建新Epoch并显式重新加入，回执丢失
返回Unknown，不把未知当失败再自动发送。动态换主、持久历史和多Realm全局协调另立规格。

Realm派生角色和成员资格，Chat只从已认证Realm链路受理，不让客户端或etcd发现授予权限。
转场不等待Chat，旧频道推送先在Realm本地失效，资格异步更新；撤销与在途发送以Chat实际串行
受理为界，不承诺与Scene转场跨服务原子生效。Realm Channel的资格保持独立，不因转场重置。

此决策不更改ADR-0011的权威玩家数据源或ADR-0015的场景持久语义；Gateway仍只登录
（ADR-0005），服务之间仍不互相include/链接（ADR-0014）。详细失败边界与C1–C5见
[Chat规格](../specs/2026-10-23-chat-reference-loop.md)。规格PR #181已合并，本ADR已接受；C1落实线契约，C2实现内部服务和排序状态机；Realm接线、双实例及组合故障边界尚待C3–C5验证。
