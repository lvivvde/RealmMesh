# KCP 安全协议

RealmMesh 不接受裸 KCP 数据包。KCP 数据报必须封装在经过认证的安全包中。

## 信任模型

票据主密钥只部署在登录服和网关服，客户端不会获得主密钥。登录成功后，登录服通过受保护的登录连接向客户端返回：

- 一个短期加密票据；
- 对应的随机会话密钥；
- 票据有效期。

票据使用 XChaCha20-Poly1305 加密，包含随机票据 ID、过期时间和会话密钥。网关解密并验证票据后，才会创建 KCP 会话。

## 数据包

协议魔数为 `RMK1`，整数使用网络字节序。

- `ClientHello`：类型、发送序号、加密票据、加密 KCP 数据报；
- `ClientData`：类型、会话 ID、发送序号、加密 KCP 数据报；
- `ServerData`：类型、会话 ID、发送序号、加密 KCP 数据报。

包头作为 AEAD associated data 参与认证。客户端到服务器、服务器到客户端分别派生独立密钥，并使用独立 nonce 域。

## 防护规则

- 票据过期、被篡改或密钥错误时不创建会话；
- 同一票据 ID 不能创建第二个会话；
- 每个方向维护 64 包滑动窗口，重复包和窗口外旧包直接丢弃；
- 只有数据包通过 AEAD 和重放检查后，才允许更新客户端 UDP 地址；
- 会话超过 `idle_timeout_ms` 没有收到认证数据后自动回收；
- KCP 未配置票据主密钥或主密钥全零时拒绝启动。

## 运维要求

- 主密钥通过密钥管理系统或环境变量注入，不提交到仓库；
- 登录服与网关服需要支持双密钥轮换后再投入生产；
- 签发票据的登录连接必须使用受保护的传输通道；
- 正式上线前需要进行协议安全审计、模糊测试、限流和抗 DDoS 压力测试。
